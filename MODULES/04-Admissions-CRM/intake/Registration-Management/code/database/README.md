# WisWits Registration Management — Database

## Overview

This directory contains the MariaDB persistence implementation for the
final integrated WisWits Registration Management module.

The database was created directly under:

```text
final/database
```

because it is being developed as part of the final module integration
rather than preserved as an earlier contributor submission.

## Schema

The implementation currently uses:

```text
client_registration_number_series
client_registrations
client_registration_documents
```

`client_registration_number_series` is the CTO-directed number-series
table.

The other two names are integration-level physical table names because
the Registration contract does not finalize their production table
names.

---

## Number-Series Rule

Registration numbers are generated by the backend.

The database stores and protects the sequence state.

Conceptually:

```text
Organization
     +
Academic Session
     ↓
Number Series
     ↓
Backend generates registration number
     ↓
Registration record
```

Example development values:

```text
ORG12-2026-0001
ORG12-2026-0002
ORG12-2026-0003
```

Registration generation must be transactional to prevent duplicate
numbers under concurrent requests.

## Demo Data

The seed file contains development/integration records only.

It must not be treated as production institutional data.

---

## Tenant Isolation

All Registration Management records are organization scoped.

The backend must use trusted organization context when accessing:

```text
client_registration_number_series
client_registrations
client_registration_documents
```

Database organization IDs alone do not replace backend authorization.

---

## Security

Never commit:

```text
.env
database passwords
production credentials
API secrets
```

The repository contains only:

```text
.env.example
```

with placeholder configuration.

---

## Host Integration

The standalone database does not create duplicate WisWits organization,
user, student or academic-session master tables.

During final SaaS integration, the schema should be mapped to the
existing host database and appropriate foreign keys added after the
canonical host identifiers are confirmed.
