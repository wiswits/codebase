# WisWits Registration Management — Final Backend

This directory contains the integrated backend implementation for the
WisWits Registration Management module.

## Stack

- Node.js
- Express
- TypeScript
- MariaDB
- REST API

## Architecture

```text
HTTP Request
     ↓
Route
     ↓
Controller
     ↓
Service
     ↓
Repository
     ↓
MariaDB
```

## Module Capabilities

The backend currently supports:

- Admission Register listing
- Registration detail retrieval
- Registration creation
- Registration updates
- Backend-generated registration numbers
- Organization/session number series
- Document checklist listing
- Document checklist creation
- Document checklist updates
- Organization-scoped repository access
- Validation
- Error handling

## Registration Number Generation

Registration numbers are generated by the backend.

The sequence is maintained in:

```text
client_registration_number_series
```

Allocation occurs inside a MariaDB transaction.

Conceptual flow:

```text
BEGIN TRANSACTION
      ↓
Lock organization/session series
      ↓
Increment sequence
      ↓
Generate registration number
      ↓
Insert registration
      ↓
COMMIT
```

Example:

```text
ORG12-2026-0004
```

The database additionally enforces registration-number uniqueness.

## Tenant Context

For standalone integration testing, the backend currently uses:

```text
DEFAULT_ORGANIZATION_ID
```

from local environment configuration.

This is temporary.

During final WisWits SaaS integration, organization context must come
from the authenticated platform identity/tenant context.

The backend must not trust a browser-supplied organization ID.

Build:


