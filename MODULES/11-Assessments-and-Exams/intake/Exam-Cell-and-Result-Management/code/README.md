# ECRMS — Exam & Result Management System

A premium, full-stack Exam & Result Management ERP built with the MERN stack.

> **Status: All 15 sidebar modules, plus Notifications, Audit Logs, CSV Import, PDF exports, a Student
> Result Portal, and Dark Mode, are fully implemented and wired end-to-end** — every page hits real API
> endpoints backed by MongoDB, not mock data.

---

## Tech Stack

**Frontend:** React (Vite), Tailwind CSS, React Router DOM, React Hook Form, TanStack Query, Axios,
React DnD, Recharts, Lucide Icons, Framer Motion, React Hot Toast

**Backend:** Node.js, Express.js, MongoDB, Mongoose, JWT Authentication, bcrypt, Multer, PDFKit,
QRCode, express-async-handler

## Setup Instructions

### Prerequisites
- Node.js 18+
- MongoDB running locally (or a MongoDB Atlas connection string)

### 1. Backend

```bash
cd backend
cp .env.example .env
# edit .env if your Mongo URI / JWT secret differs from the defaults
npm install
npm run seed   # populates the database with realistic demo data
npm run dev    # starts the API on http://localhost:5000
```

### 2. Frontend

```bash
cd frontend
cp .env.example .env
npm install
npm run dev    # starts the app on http://localhost:5173
```

Open http://localhost:5173 — you'll land on the login screen with clickable demo account buttons.

## Suggested walkthrough order

The modules feed into each other, so trying them in this order shows the full exam lifecycle:

1. **Exam Scheduler** — schedule an exam for Class 10 A.
2. **Question Bank** — add a few questions if you want more variety (some are pre-seeded).
3. **Blueprint Builder** — create/save a chapter-wise blueprint for a subject.
4. **Auto Paper Generation** — generate paper sets from that blueprint.
5. **Seating Plan** — auto-arrange seating for the scheduled exam, then drag to swap a couple of seats.
6. **Invigilation** — auto-assign invigilators for the exam date.
7. **Hall Tickets** — bulk-generate hall tickets (with QR codes) and download a PDF.
8. **OMR Evaluation** — upload a sample image/PDF and click Evaluate to simulate scoring.
9. **Result Entry** — enter marks for the class in the grid.
10. **Moderation** — apply a moderated mark adjustment to a student.
11. **Result Processing** — click Process Results to compute grades, ranks, and pass/fail.
12. **Result Publishing** — move the result batch through Draft → Review → Approve → Publish.
13. **Reports & Analytics** — view the pass/fail trend and subject-wise performance once a few exams
    have been processed.
14. **Settings** — edit institution details, the grading scale, manage users under **Users & Roles**,
    and review the **Audit Logs** tab for a trail of the actions above.
15. Log out and log back in as `student1@ecrms.edu` to see the **Student Result Portal** — it only shows
    once a result batch has been published (step 12) and includes a per-exam marksheet PDF download.
16. Click the moon/sun icon in the top bar to try **Dark Mode**, and the bell icon to check the
    **Notifications** that were generated by steps 7 (Hall Tickets) and 12 (Result Publishing).

## What's implemented

- **Authentication & RBAC** — JWT auth with bcrypt hashing, protected routes, and role-based middleware
  for `admin`, `exam_controller`, `teacher`, `student`, `invigilator`, `principal`.
- **Dashboard** — live stats, upcoming exam list, pass/fail donut chart, 6-month exams bar chart.
- **Exam Scheduler** — calendar month view, create/delete exams, cascading class → subject dropdowns.
- **Question Bank** — searchable/filterable/paginated table, add questions across 6 question types,
  Bloom's level & difficulty tagging.
- **Blueprint Builder** — chapter-wise weightage, marks, Bloom's-level and difficulty distribution grid.
- **Auto Paper Generation** — pulls matching questions from the bank against a blueprint's targets,
  generates multiple sets, full paper preview.
- **Seating Plan** — auto-arranges the class roster (linear/zigzag/shuffled), true drag-and-drop seat
  swapping, persists manual edits.
- **Invigilation** — auto-assigns primary/secondary invigilators to every exam on a chosen date.
- **Hall Tickets** — bulk-generates tickets with real QR codes and downloadable A5 PDFs (PDFKit).
- **OMR Evaluation** — real file upload (Multer, JPG/PNG/PDF) with a simulated auto-scoring pass.
- **Result Entry** — marks-entry grid pre-populated from the class roster, bulk save.
- **Moderation** — per-student mark adjustment queue with an audit trail.
- **Result Processing** — computes percentage, grade (against the configurable grading scale), rank,
  and pass/fail from entered/moderated marks; grade-distribution donut chart.
- **Result Publishing** — Draft → Review → Approve → Publish workflow stepper.
- **Reports & Analytics** — pass/fail trend line chart and subject-wise average performance bar chart
  across processed exams.
- **Settings** — General institution details, configurable Grading Scale, a **Users & Roles** tab with
  full user CRUD (this doubles as the User Management module), and an **Audit Logs** tab.
- **Notifications** — an in-app bell dropdown (unread count, mark-as-read/mark-all-read) that receives
  real notifications when hall tickets are generated and when results are published.
- **Audit logging** — key actions (exam create/delete, auto-assign invigilators, result processing,
  result status changes) are written to the `AuditLog` collection and viewable under Settings.
- **Email on Result Publish** — when a result batch is published, ECRMS emails every student their
  score/grade via Nodemailer (falls back to a console log if SMTP isn't configured, so local dev never
  breaks).
- **CSV Import** — Question Bank supports downloading a CSV template and bulk-importing questions from
  a filled-in CSV.
- **PDF Exports** — download a full question paper (Paper Generation), an individual student marksheet
  (Result Processing), and hall tickets (already in Pass 3) as PDFs.
- **Student Result Portal** — students get a dedicated "My Results" view (and a filtered sidebar) showing
  their published results, stats, and a marksheet download button per exam.
- **Dark Mode** — a toggle in the top bar switches the whole app between light and dark themes, persisted
  in local storage.
- **Mongoose models for every module** in the PRD, with realistic seed data for classes, subjects,
  students, teachers, exams, a sample blueprint, and sample questions.

## Known simplifications

- OMR evaluation uses a simulated scoring pass (randomized accuracy/marks in a realistic range) rather
  than actual image-recognition — wiring in a real OMR/bubble-detection pipeline is a drop-in swap of
  `evaluateOMRSheet` in `omrController.js`.
- Email delivery requires real SMTP credentials in `.env` (`EMAIL_HOST`/`EMAIL_USER`/`EMAIL_PASS`) —
  without them, `sendEmail()` logs to the console instead of failing, so local development still works.
- The CSV importer for Question Bank uses a lightweight built-in parser (no external dependency) suited
  to the documented template; it doesn't handle quoted commas inside a field.

## Deployment

- **Backend** → Render. A `render.yaml` is included at the project root — connect the repo in Render and
  it will pick up the service definition (set `MONGO_URI`, `CLIENT_URL`, and the `EMAIL_*` vars in the
  dashboard). Make sure the `uploads/` folder is on persistent storage (or swap Multer's disk storage for
  S3/Cloudinary) since most PaaS filesystems are ephemeral.
- **Frontend** → Vercel. A `vercel.json` is included in `frontend/` with the SPA rewrite rule already
  configured. Set `VITE_API_URL` to your deployed backend's `/api` URL in the Vercel project settings.
